# BitChat

<!-- impeccable:product-schema 1 -->

## Platform
android

## Stack
React Native CLI and TypeScript, Android native bridges. The user delegated implementation choices and requested an installable Android output.

## Users
Turkish-speaking people preparing for, or affected by, disasters; neighbors sharing essential supplies.

## Product Purpose
An offline-first communication and mutual-aid application that can be opened and exercised without a drone, server account, or special hardware.

## Operating Context
Unreliable internet, denied device permissions, low batteries, absent peers and repeated delivery attempts are normal states. A single-device exercise must remain distinct from actual communication.

## Capabilities and Constraints
Local persistent messages, explicit SOS composition, offline priority classification, local aid offers and needs, an interactive offline map and diagnostic exercises. Device-to-device communication requires supported phones and device validation. No AFAD endpoint, official map dataset, keys, drone, or remote service was supplied. Never imply a queued message was delivered or emergency services were contacted. No claimed ultrasonic rescue capability. An unencrypted public channel must be labeled public. Emergency assistance never requires rewards.

## Brand Commitments
BITCHAT; Turkish UI; modern, usable and interactive. The user explicitly authorized autonomous design decisions.

## Evidence on Hand
User project brief; repository initially empty. Any exercise fixtures must be visibly labeled and isolated from actual records.

## Product Principles
1. Preserve user data offline and report failures honestly.
2. Keep emergency actions accessible and deliberate.
3. Separate local saving, peer receipt and institutional delivery.
4. Show absent capabilities rather than inventing successful connections.

## Accessibility & Inclusion
Assumption from the disaster context: high contrast, large touch targets, readable type and semantic labels; do not rely on color alone.
